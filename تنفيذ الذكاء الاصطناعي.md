# تنفيذ الذكاء الاصطناعي

## الحالة

الهدف من هذا الملف هو سجل التنفيذ الموحد لمسار ترقية الذكاء الاصطناعي في FLIXO-AI-TOOLS.
القاعدة الحاكمة: Agent ليس Authority؛ الـCanonical Registry هو Authority.

## المرحلة الأولى — منفذة

تم دمج الحزمة الأولى في مسار execution:

1. Failure Intelligence Agent
   - يبني fingerprint حتمي للفشل.
   - يطبع failure features وnormalized failure.
   - يربط الدليل مباشرة بمسار الاستهداف بدل إنشاء فرضيات غير قابلة للإثبات.

2. Exact Targeting Agent
   - يعيد استخدام الاختبار/الملف الموجود.
   - يمنع إنشاء اختبارات جديدة.
   - يتحقق من هوية هدف Playwright عبر --list ويغلق التنفيذ عند zero/multiple matches.
   - يبقى baseline=3 وafter=2 داخل عقد التحقق الموجود في Auto-Repair.

3. Impact Engine
   - يستخدم محرك scripts/ci/impact/engine.ts الموجود بدل إنشاء محرك أثر منافس.
   - يحسب العقود المتأثرة ومستوى التصعيد L0-L3 من الملفات المتغيرة.
   - أي ملف غير مغطى بقاعدة يصبح conservative L3.

4. CI Orchestrator
   - لا ينفذ workflows بنفسه.
   - يبني خطة حتمية: targeted-only أو targeted+static/build أو full canonical CI.
   - جهة الإرسال الوحيدة تبقى Daily·FLIXO Green Gate.
   - جهة الإصلاح الوحيدة تبقى FLIXO Auto Repair Bot.

5. Concurrency Guard
   - يثبت expected SHA == local SHA == origin/execution SHA قبل وبعد مرحلة الإصلاح.
   - أي حركة متزامنة للرأس تفتح fail-closed بدل دمج أو overwrite.

## المرحلة الثانية — منفذة

### Repair Strategy Agent
توحيد اختيار الاستراتيجية مع `repair-strategy.mjs` عبر دوران حتمي مرتبط بالمحاولة، مع إبقاء repair attempt إلزاميًا.

### Test Set-Cover Minimizer
تطبيق Weighted Greedy Set Cover على `scripts/ci/test-impact-map.json` لاختيار أقل مجموعة أوامر تغطي مجالات التغيير؛ الملفات المجهولة تتحول إلى full canonical verification.

### Security Guardian Agent
حارس fail-closed يمنع الأسرار وworkflow mutations وcontrol-plane mutations ويعيد استخدام `repository-security-baseline.mjs` كمرجع.

### Release Integrity Agent
تثبيت سلسلة source SHA → execution SHA → PR head → evidence → main/promotion → merge → deployment identity.

## المرحلة الثالثة — CANDIDATE / NEEDS DEVELOPMENT

### Failure Clustering
تجميع الأعطال المتكررة حسب fingerprint وroot cause class وaffected contract بدل التعامل معها كأحداث منفصلة.

### Bayesian Confidence Calibration
تحديث ثقة كل قاعدة إصلاح من نتائج success/failure باستخدام Beta-Binomial مع فصل external blockers عن repair outcomes.

### Contextual Bandit Strategy Selection
اختيار الاستراتيجية التالية بناءً على سياق الفشل وتكلفة الإصلاح ونتائج الاستراتيجيات السابقة، مع exploration محدود وfail-closed.

### Predictive Anomaly Detection
اكتشاف انحراف نمط CI أو زيادة latency/failure recurrence قبل الوصول إلى RED صريح، دون أن يصبح هذا النظام مصدر قرار مستقل.

### Learning / Evolution Agent
ترقية القواعد فقط من evidence verified، مع provenance كامل وanti-pattern memory.

## مبادئ التنفيذ

- مصدر الحقيقة واحد لكل قدرة.
- لا Agent يعدل المستودع مباشرة خارج executor الموثوق.
- لا Agent يعلن GREEN.
- لا اختبار جديد ينشأ تلقائيًا من فشل لم يثبت exact target.
- Targeted verification ليست بديلًا عن Canonical CI.
- أي ambiguity أو concurrency drift = fail closed.
- لا third branch.
- لا self-dispatch.
- لا source mutation لإخفاقات provider/external tooling.
