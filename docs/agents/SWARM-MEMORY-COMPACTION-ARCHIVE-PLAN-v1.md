# FLIXO Swarm OS — Memory Compaction & Rebuild Plan v1\n\nThe CELL-001..CELL-200 pool is retired. This is a future-use bounded architecture, not automatic reprovisioning.\n\n| Layer | Purpose | Policy |\n|---|---|---|\n| L0 | working | task-local, discard at boundary |\n| L1 | session | bounded, session-scoped |\n| L2 | personal | per-bot; knowledge-only export |\n| L3 | episodic | mission outcomes + provenance |\n| L4 | semantic | merged claims + decayed confidence |\n| L5 | canonical | current + verified + exact-SHA-backed only |\n\n## Governor\n- Deduplicate before compaction.\n- Preserve provenance, SHA, evidence count and verification state.\n- Quarantine stale, revoked, contradicted and unproven knowledge.\n- Archive rather than delete historical knowledge.\n- Produce a deterministic digest after compaction.\n- Rebuild only from count + digest + current exact SHA.\n\n## Poisoning defense\n- Generated/web-only claims do not enter L5 directly.\n- Missing provenance/evidence rejects promotion.\n- SHA mismatch rejects promotion.\n- Contradiction blocks promotion.\n- Historical proof is advisory only.\n\n## Revalidation\nKnowledge and skills decay; promotion must be reversible through canary/shadow evaluation.\n\n## Repair-to-learning loop\nOBSERVE → RCA → PROVISIONAL LEARNING → TARGETED RECHECK → CANONICAL GREEN → PROMOTE\n
