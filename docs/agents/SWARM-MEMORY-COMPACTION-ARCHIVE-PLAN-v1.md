# FLIXO Swarm OS — Memory Compaction & Rebuild Plan v1\n\nThe CELL-001..CELL-200 pool is retired. This is a future-use bounded architecture, not automatic reprovisioning.\n\n| Layer | Purpose | Policy |\n|---|---|---|\n| L0 | constitution | highest-level advisory baseline; never mutation authority |\n| L1 | canonical project memory | canonical project facts; fresh evidence still dominates |\n| L2 | shared skill knowledge | skill/capability knowledge; evidence-linked and decaying |\n| L3 | cell personal memory | per-logical-bot knowledge only; never authority/permissions |\n| L4 | current mission memory | active mission context + evidence; discarded/archived at boundary |\n| Identity model | 200 fixed logical bot identities | memory/routing index only; operational activation remains centrally governed |\n\n## Governor\n- Deduplicate before compaction.\n- Preserve provenance, SHA, evidence count and verification state.\n- Quarantine stale, revoked, contradicted and unproven knowledge.\n- Archive rather than delete historical knowledge.\n- Produce a deterministic digest after compaction.\n- Rebuild only from count + digest + current exact SHA.\n- The 200 identity catalog is not a worker pool and must not provision/wake/assign bots.\n\n## Poisoning defense\n- Generated/web-only claims do not enter L5 directly.\n- Missing provenance/evidence rejects promotion.\n- SHA mismatch rejects promotion.\n- Contradiction blocks promotion.\n- Historical proof is advisory only.\n\n## Revalidation\nKnowledge and skills decay; promotion must be reversible through canary/shadow evaluation.\n\n## Repair-to-learning loop\nOBSERVE → RCA → PROVISIONAL LEARNING → TARGETED RECHECK → CANONICAL GREEN → PROMOTE\n
