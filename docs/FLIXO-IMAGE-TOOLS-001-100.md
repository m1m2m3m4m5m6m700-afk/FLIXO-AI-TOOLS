Priority is determined by:
1. Result quality rather than raw tool count.
2. Recurring user value.
3. Competitive capability coverage.
4. Fit with the FLIXO execution architecture.

## FLIXO interface direction

The catalog is intended to support an agent-first experience rather than a 100-button interface:

```text
User Request
→ Image Analysis
→ Goal Detection
→ Capability Discovery
→ Tool/Capability Selection
→ Plan
→ Execution
→ Output Verification
→ Error/Quality Repair
→ Before/After Comparison
→ Delivery
```

The agent is not the source of truth and must not invent tool IDs or bypass the canonical Registry. A discovered capability becomes executable only after canonical registration, contract validation, safety policy, executor binding, and verifier coverage.

## Classification model for the 100

These capabilities are organized as candidate capabilities that can later be grouped into:
- Core tools
- Professional tools
- Specialized tools
- Composite tools
- Inspection and quality tools
- Arabic/localized use cases
- Commerce/content workflows

Grouping does not activate a tool and does not replace canonical Registry status.
