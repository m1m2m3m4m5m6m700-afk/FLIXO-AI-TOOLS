# 3. Dual Workflow — عقد المنتج الإلزامي

## 3.1 Agent Guided Workflow
`Upload -> Natural Language -> Intent -> Parameters -> Plan -> Canonical Capability -> Execution Gate -> Executor -> Verifier -> Result`

الوكيل:
- يفسر intent.
- يقترح plan.
- يستخدم canonical capabilities فقط.
- لا ينفذ arbitrary code.
- لا يملك raw File/Blob bytes.
- لا يختار executor أو verifier من خارج canonical boundary.
- عند ambiguity/unsupported/unsafe/failure: fail closed أو manual fallback.

## 3.2 Manual Standalone Workflow
`Browse Tools -> Tool -> File Input -> Execute -> Verify -> Output`

المانيوال:
- لا يعتمد على Agent Router.
- يستخدم نفس canonical capability/executor/verifier/output contract.
- يمكن للمستخدم تجاوز Agent بالكامل.

## 3.3 Equivalence rule
عند تنفيذ نفس capability عبر المسارين:
- نفس canonical capability;
- نفس execution contract;
- نفس executor authority;
- نفس verifier;
- نفس output schema.

اختلاف UX مسموح. اختلاف authority أو execution contract غير مسموح.

# 6. Model Governance + Sustainability

## 6.1 Model admission
الموديل usable فقط إذا:
- license evidence PASS;
- provenance PASS;
- policy/evaluation PASS;
- lifecycle = ACTIVE;
- task compatible;
- artifact identity ثابت حيث ينطبق.

الحالات:
`PASS / REVIEW_REQUIRED / BLOCKED / UNKNOWN`

UNKNOWN/REVIEW/BLOCKED/QUARANTINED = fail closed.

## 6.2 Model independence
- runtime selection من admitted Model Fabric فقط.
- لا اختيار arbitrary model من env/config.
- provider SDK خلف adapter.
- لا model registry ثانية.
- model = planning/proposal resource.

## 6.3 Fallback
`Primary -> Candidate 2 -> Candidate 3 -> deterministic local planner`

القواعد:
- max provider calls = 3.
- circuit failure threshold = 2.
- cooldown = 30s.
- retry loops disabled.
- no automatic model promotion.
- fallback يحافظ على canonical ToolPlan.

## 6.4 Sustainability
يفصل بوضوح:
- third-party base weights;
- FLIXO adapters/LoRA;
- FLIXO datasets;
- third-party datasets;
- evaluation corpus;
- runtime/policy code.

ولا يجوز اعتبار third-party model FLIXO-owned بلا دليل.
Training-data provenance منفصل عن model-license status.
Trademark/patent/AUP/hosting/redistribution restrictions منفصلة عن copyright.

- `retryable`

## 13.3 Idempotency
العقود:
- executionId;
- idempotencyKey;

Test limits and race behavior before changing resilience parameters.

## R-041 — Build Artifact Identity
First inspect whether deterministic build/lockfile/assets prove runtime identity.
If not, add the least-complex artifact identity assertion.

## R-042 — Memory Advisory Boundary
Treat memory as untrusted until data-flow proves otherwise; test valid-but-poisoned parameters.

## R-043 — Binary Buffer / TypedArray Isolation
Attack nested TypedArray, ArrayBuffer, ImageData, Blob, transferables, shared-memory semantics and mutation during retry/fallback.
`Object.freeze()` alone is not sufficient proof.

## R-044 — Verifier Input Independence
Verifier should reason from actual artifact + expected contract, not executor metadata alone.

## R-045 — Generated Runtime / Dependency Identity
Account for lockfile/generated assets/worker/WASM identity where they materially affect execution.
Do not add crypto unless required by demonstrated threat model.
