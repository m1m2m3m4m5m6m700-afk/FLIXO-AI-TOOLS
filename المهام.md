# Safe Repair Agent Execution

This document defines the bounded mutation contract for the **Repair Agent / Execution Agent**. It is not a Task Agent contract.

The Task Agent is preparation-only. It may inspect, reason, prepare a bounded packet and hand off. Mutation starts only after the authorized mutation agent passes protocol admission and ownership locks.

## COUNCIL-FIRST ADMINISTRATION
The Council President (`assistantController`) is the highest repository administration authority. Any Council message, comment, wake, question, or invocation is P0 and receives an immediate receipt/response before lower-priority repair work. Safe-boundary preemption may reorder queued work; it must not corrupt in-flight source mutation. Stale/conflicting Council input is answered immediately as fail-closed evidence.

## Canonical lifecycle

```text
FAILURE
  ↓
capture exact SHA + run + job + evidence
  ↓
diagnosis + RCA
  ↓
Task Agent preparation
  ↓
Executive / Coordination admission
  ↓
Repair Agent or Execution Agent mutation
  ↓
targeted regression + affected-contract verification
  ↓
canonical verification
  ↓
certification
```

## Mutation authority

Only agents admitted by `scripts/ci/repair-protocol.mjs` may mutate.

Current mutation roles:

`repairAgent`
`executionAgent` (non-canonical role; not mutation-authorized)

The **Task Agent is explicitly not a mutation role**.

The central admission rule is enforced by `assertAgentAdmission({ actor, mutation: true, ... })`. A `taskAgent` mutation request fails closed with `REPAIR_PROTOCOL_MUTATION_ROLE_BLOCKED`.

## Branch and scope invariants

- `execution` is the sole working/repair/integration branch.
- `main` is the sole production/source-of-truth branch.
- No third branch exists as an active execution path.
- Mutation requires current protocol/session admission.
- Protected control-plane files remain protected.
- Scope and RCA ownership are established before mutation.

## Task Agent handoff boundary

The Task Agent may provide:

`taskId + baselineSha + scope + dependencies + preparedChanges + verificationPlan + proofObligations + prompt provenance`

The downstream mutation agent MUST independently revalidate:

- exact baseline SHA;
- RCA/evidence;
- prompt selection;
- ownership;
- dependencies;
- scope;
- security/control-plane policy;
- verification obligations.

A Task Agent packet is never a mutation authorization.

## Evidence and closure

Every mutation retains:

`repairChainId + repairAttempt + failureRunId + failedSha + failureFingerprint + causalEvidence + rootCause + sourceCorrection + regressionProof + canonicalExactShaEvidence + preventionOutcome`

Source correction must precede regression-only hardening. A test cannot substitute for the causal source repair.

Closure remains external to the mutation agent:

`mutation → targeted verify → affected graph → regression → recurrence → certification`

No Repair Agent or Task Agent may declare final GREEN/CLOSED/VERIFIED without canonical certification evidence.

## Trust boundary

Trusted controller policy, protocol definitions and canonical memory remain authoritative. Derived agent learning is supporting evidence only.

Historical evidence cannot certify a newer SHA.

## Failure and escalation

Repeated failure without verifiable progress is escalated through the existing repair supervisor/circuit-breaker path. External provider failures remain `BLOCKED_EXTERNAL` and are never converted into an internal source RCA without independent evidence.

2. SINGLE-DISPATCH IDEMPOTENCY

```text
DISPATCH_KEY = TARGET_SHA + FAILED_RUN_ID + FAILURE_FINGERPRINT
```

- نفس key = dispatch واحد فقط.
- duplicate dispatch = NO-OP.
- يجب حفظ key مع الحالة والـlease والـevidence.
- لا يسمح بإصلاحين متزامنين لنفس target SHA + same failure.

3. REPAIR LEASE + STALE RECOVERY

كل repair lease يسجل:

```text
dispatchKey
owner
acquiredAt
expiresAt
heartbeat
```

القواعد:

```text
ACTIVE + VALID LEASE
→ CONTINUE

ACTIVE + EXPIRED LEASE
→ STALE
→ SAFE RECOVERY
```

لا يجوز استعادة lease منتهية على أنها نشطة دون revalidation.

4. CONCURRENCY POLICY

```text
SAME SHA + SAME FAILURE
→ MAX 1 ACTIVE REPAIR

SAME SHA + DIFFERENT FAILURES
→ SERIALIZED / BOUNDED

DIFFERENT SHA
→ INDEPENDENT EXECUTION
```

5. UNIFIED REPAIR BUDGET

الحدود المرجعية:

```text
3   attempts / fingerprint
8   max files / repair operation
12  max repair cycles / worker
3   max stalled cycles
300 max changed lines
```

ممنوع وجود active control limit غير محدود أو placeholder مثل 1,000,000 كحد تشغيلي فعلي.

عند الاستنفاد:

```text
BUDGET_EXHAUSTED
→ NO AUTO-REPAIR
→ ERROR MEMORY
→ BLOCKED / HUMAN REVIEW
```

6. POLICY / INVARIANTS PRE-MUTATION CHECK

قبل أي mutation يجب التحقق من:
- scope.
- authority.
- branch.
- budget.
- protected paths.
- control-plane immutability.
- baseline SHA.
- dispatch idempotency.
- active lease.
- evidence freshness.
- latest applicable Code Scout evidence for the same scope + baseline SHA.
- scout freshness, consumed/rejected findings, affected scope, and decisionTrace.
- canonical assertion owner.
- affected dependency / contract graph closure.

SCOUT_MISSING / SCOUT_STALE / SCOUT_SCOPE_MISMATCH / SCOUT_SHA_MISMATCH / AUTHORITY_CONFLICT / MISSING_GRAPH_CLOSURE
→ FAIL-CLOSED.

UNKNOWN / CONFLICT / MISSING PROOF = FAIL-CLOSED.

يحظر على Auto-Repair تعديل أو اعتماد تغييرات ذاتية على:

8. REPAIR LOOP + RACE INVALIDATION

```text
REPRODUCE
→ REPAIR
→ VERIFY
→ HEAD / RACE VALIDATION
```

إذا تغير HEAD:

```text
HEAD CHANGED
→ DISCARD REPAIR RESULT
→ RE-READ CURRENT HEAD
→ RECOMPUTE RCA
→ REQUALIFY REPAIR
→ RACE_DETECTED
```

أي evidence أو patch نتج قبل تغير target SHA لا يعاد استخدامه تلقائيًا.

9. TARGETED REGRESSION SENTINEL

بعد repair يجب إثبات:

```text
ORIGINAL PASS
∧ RELATED PASS
∧ PROTECTED STILL PASS
```

فشل أي طبقة = repair ineffective + Error Memory update + anti-pattern + rollback إذا كانت mutation قد نُشرت.

10. EVIDENCE PROVENANCE CHAIN

السلسلة الإلزامية الكاملة، مع المحافظة على Exact-SHA lineage الحالية:

```text
ASSERTION ID
→ EXECUTION UNIT
→ SOURCE / BASE SHA
→ RUN ID
→ JOB ID / STEP
→ ENVIRONMENT / RUNTIME
→ ARTIFACT ID
→ ARTIFACT DIGEST
→ RESULT
→ RCA
→ CERTIFICATE ID
→ MERGE SHA
```

قواعد الربط:
- كل execution unit يجب أن يرتبط بـcanonical assertion owner.
- لا يُقبل evidence خارج affected dependency / contract graph.
- provenance التاريخية ليست Current Evidence لمجرد وجودها.
- كل evidence يحمل:
  - timestamp
  - schemaVersion
  - exact target SHA
  - execution identity
  - artifact identity/digest عند وجود artifact.

التحقق:

```text
SHA mismatch
OR artifact digest mismatch
OR certificate identity mismatch
→ EVIDENCE INVALID
→ RE-CERTIFY
```

لا تسمح شهادة قديمة بإثبات SHA جديد.

11. CERTIFICATION LOCK

بعد Certification:

```text
CERTIFIED SHA
→ CERTIFICATION LOCK
→ MERGE GATE
```

إذا تغير execution SHA بعد certification:

```text
SHA_CHANGED
→ CERTIFICATION_INVALID
→ RE-CERTIFY
```

12. MERGE IDENTITY

الترقية المسموحة:

```text
CERTIFIED EXECUTION SHA
→ MERGE GATE
→ FAST-FORWARD ONLY
→ main = CERTIFIED SHA
→ POST-MERGE EXACT-SHA READBACK
```

شرط الإغلاق:

```text
MAIN SHA == CERTIFIED SHA
```

أي merge commit / squash / rebase بعد certification يلغي Exact-SHA identity لهذه المهمة ما لم تتم إعادة certification على الناتج النهائي.

13. EXTERNAL BLOCKER LIFECYCLE

```text
BLOCKED_EXTERNAL
→ REPROBE_PENDING
→ SIGNATURE_UNCHANGED
→ HOLD
```

أو:

```text
BLOCKED_EXTERNAL
→ REPROBE_PENDING
→ SIGNATURE_CHANGED
→ REQUALIFY
→ INTERNAL / EXTERNAL
```

القواعد:
- لا code mutation لمعالجة blocker خارجي.
- لا fake internal RCA.
- لا gate bypass.
- لا false GREEN.

### 16.2 — UNIFICATION RULES

1. **ONE OWNER PER INVARIANT.** أي invariant يجب أن يملك تنفيذًا واحدًا واختبارًا حاكمًا واحدًا. يمكن وجود مستهلكين متعددين، لكن لا يجوز وجود مصدرين متنافسين.

2. **ONE IDENTITY CHAIN.** لا تُنشأ هوية جديدة لتفادي `repairChainId` أو `run identity` أو `checkpoint identity`. أي جلسة/إصلاح/شهادة تربط بالهوية الموجودة.

3. **ONE EVIDENCE LINEAGE.** كل إثبات يمر عبر الـexecution graph والـcanonical certification؛ لا تقبل task محلية باعتبارها شهادة مستقلة.

4. **KNOWLEDGE ≠ AUTHORITY.** طبقة Knowledge تدعم القرار وتقدم السياق والفرضيات؛ لا تمنح mutation أو promotion authority جديدة.

5. **DIAGNOSIS ≠ EXECUTION.** Code Scout / RCA / learning يمكنها التشخيص أو التوصية، لكن mutation تمر فقط عبر Execution Control + Task Agent + حدود الإصلاح.

6. **CHECKPOINT ≠ CERTIFICATE.** الـCheckpoint يثبت snapshot/identity؛ Certification هي سلطة GREEN. لا يختلط الدوران.

7. **HISTORICAL ≠ CURRENT.** أي mechanism تاريخية لا تصبح Current Evidence إلا بعد إعادة إثباتها على SHA الحالي.

8. **EXTERNAL ≠ SOURCE FAILURE.** GitHub/Vercel/provider/infrastructure blocker يبقى `BLOCKED_EXTERNAL` ولا يتحول إلى patch في source بدون causal proof.

9. **MERGE ≠ CERTIFICATION.** لا تُنشأ شهادة بعد merge لإثبات SHA قديم؛ certification يجب أن تقفل exact final SHA.

10. **DELETE/CONSOLIDATE ONLY AFTER PROOF.** دمج أو حذف أي duplicate يحتاج search → dependency proof → impact check → replacement owner → regression. لا حذف تخميني.
