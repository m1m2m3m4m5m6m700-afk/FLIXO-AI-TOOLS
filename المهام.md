### UNIFORM STEP CONTRACT

كل خطوة تنفذ بهذا القالب:

`PRECHECK → REPRODUCE/BASELINE → IMPLEMENT/REPAIR → TARGETED TEST → CONTRACT VERIFY → ADVERSARIAL CHECK → CANONICAL CI → RECORD EVIDENCE → PASS/RETRY`

حالات الخطوة:
`READY → RUNNING → PASS`
أو:
`READY → RUNNING → FAIL → RCA → REPAIR → RUNNING → PASS`

ولا توجد حالة `BLOCKED` تشغيلية؛ توجد فقط `DEPENDENCY_REPAIR_REQUIRED` وتعود بعدها الخطوة إلى `READY`.

### AUTOMATIC FAILURE ROUTING

1. **RED test:** حدد الاختبار الفاشل + failure fingerprint.
2. **RCA:** اربط الفشل بالملف/العقد/invariant.
3. **Repair:** أنشئ إصلاحًا مصنفًا `[REPAIR:<ID>] [WP:<ID>]` داخل `execution`.
4. **Targeted recheck:** أعد الاختبار المتأثر أولًا.
5. **Regression:** تحقق من العقود المجاورة.
6. **Canonical CI:** أعد البوابات المطلوبة على SHA الجديد.
7. **Rebind:** اجعل SHA الجديد هو المرجع الوحيد.
8. **Continue:** انتقل تلقائيًا للخطوة التالية فقط بعد PASS.

### AUTOMATIC STALE-SHA HANDLING

عند تغير HEAD أثناء التنفيذ:
`STOP STALE WORK → READ NEW HEAD → REBASE/REBASE-LOGICAL-STATE → INVALIDATE STALE EVIDENCE → RERUN CURRENT STEP`

لا يُعاد استخدام evidence القديم لإثبات GREEN.

9. `CERTIFY`: اربط الأدلة بالـexact SHA الحالي.
10. `LEARN`: سجّل lesson + anti-lesson + recurrence prevention.
11. `ADVANCE`: انتقل إلى الخطوة التالية.
