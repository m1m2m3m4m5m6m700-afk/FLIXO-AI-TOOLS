# FLIXO-AI-TOOLS — بوابة المهام التنفيذية

> **الإصدار:** TASK-GATE v2.0
> **الحالة:** ACTIVE / REQUIRED AGENT GATE
> **الغرض:** حفظ قائمة العمل المفتوحة وخطة التنفيذ الكاملة بحيث يمكن لأي وكيل استئناف العمل من الحالة الفعلية دون فقدان المهام أو اختراع مهام جديدة.
> **مصدر الحقيقة التشغيلي:** `main` + `PROJECTS.md` + هذه الوثيقة + العقود الحاكمة + Fresh Exact-SHA Evidence.
> **ممنوع اعتبار أي SHA أو Evidence تاريخي دليلًا للحالة الحالية دون إعادة التحقق.**

## 0. قاعدة الدخول الإلزامية

قبل أي قراءة للكود أو تعديل أو اختبار أو تشغيل CI يجب على كل وكيل تنفيذ التسلسل التالي:

```text
PROJECTS.md
→ المهام.md
→ AGENTS.md
→ INGEST HANDOFF
→ RESOLVE EXACT main SHA
→ IDENTIFY ACTIVE TASK
→ READ AUTHORITATIVE CONTRACT
→ RCA / SCOPE LOCK
→ EXECUTE MINIMUM PROVEN CHANGE
→ TARGETED REGRESSION
→ AFFECTED CONTRACT GRAPH
→ EXACT-SHA PROOF
→ UPDATE PROJECTS.md + المهام.md
→ HANDOFF / LOGOUT
```

عدم قراءة `المهام.md` يعني عدم امتلاك نطاق تنفيذ معتمد.

## 1. مبادئ الالتزام الصارمة

1. `main` هو مصدر الحقيقة الحالي.
2. `ACTIVE` فقط هو التنفيذ المصرح به مباشرة.
3. `LOCKED` يعني dependency-gated وليس منسيًا.
4. `CANDIDATE ≠ ACTIVE`.
5. `DEFER ≠ forgotten`.
6. `BLOCKED ≠ STOP`.
7. `UNKNOWN ≠ PASS`.
8. `INCOMPLETE ≠ SUCCESS`.
9. لا Green من CI جزئي، أو فرع غير مدمج، أو SHA مختلف، أو Evidence قديم، أو provider bypass.
10. لا تعطيل اختبارات، ولا تخفيف assertions، ولا حذف coverage، ولا تحويل failure إلى warning لإخفاء defect.
11. لا LLM-direct production execution ولا تجاوز authorization/policy/approval/evidence.
12. لا duplicate registry / validator / truth store / execution owner بلا حاجة مثبتة.
13. كل defect يبدأ بـRCA واضح، وكل RCA يغلق فقط بالسبب الجذري + regression + contract proof + fresh exact-SHA evidence.
14. عند تحرك `main` يجب إعادة حل SHA قبل الاستمرار.
15. لا تُضاف مهمة جديدة إلى القائمة إلا بمصدر حاكم، owner، invariant، exit criteria، وnext deterministic action.

## 2. بروتوكول حفظ المهام وعدم فقدانها

هذه الوثيقة هي **Open Task Queue**. لا يُفترض أن يكون لها حالة فارغة بسبب حذف معلومات العمل.




## 11. بروتوكول الحذف بعد التنفيذ

الهدف من الحذف هو تنظيف Open Task Queue أو retire مصدر قديم، وليس محو provenance.

لا يجوز حذف مهمة أو مصدر حاكم من `main` لمجرد اكتمال تعديل محلي أو نجاح جزئي. الحذف أو التقاعد لا يُعتبر مكتملًا إلا عند تحقق العقد التالي كاملًا:

```text
MERGED TO MAIN
∧ EXACT MAIN SHA CONFIRMED
∧ TARGETED TESTS PASS
∧ REQUIRED CI / CERTIFICATION PASS
∧ TASK INVARIANT PROVEN
∧ NO DEPENDENT REPAIR OPEN
∧ CLOSURE EVIDENCE RECORDED
∧ PROJECTS.md CLOSED HISTORY UPDATED
∧ NEXT TASK / DEPENDENCIES UPDATED
```

`حذف المهمة قبل اكتمال أي شرط = PROTOCOL VIOLATION`

عند retire لوثيقة roadmap أو مصدر تخطيط قديم، يجب أولًا إثبات نقل المعلومات ذات القيمة إلى المصدر الحاكم، وإثبات عدم وجود مراجع تنفيذية غير منقولة، ثم تنفيذ الحذف أو إبقاء legacy pointer وفق الحاجة. يجب أن يبقى closed history وprovenance قابلين للتتبع.

### 21.16 Safety Rules Carried Forward

1. `main` مصدر الحقيقة الإنتاجية.
2. لا تعديل مباشر على `main`.
3. كل تغيير عبر PR.
4. لا dependency جديدة بلا حاجة مثبتة.
5. لا refactor مع feature غير مرتبطة في PR واحد.
6. لا حذف تاريخي لمجرد التبسيط.
7. لا merge قبل إثبات SHA المحدد.
8. النجاح يُقاس بالأدلة.
9. لا abstraction قبل الحاجة الفعلية.
10. لا نرفع التعقيد أسرع من نمو الأدوات.
